เอกสารนี้เป็นประวัติการทบทวนก่อนเปลี่ยนขอบเขต ปัจจุบันใช้ระบบคำนวณ เก็บข้อมูล และรายงานตาม [system-review.md](system-review.md) ขั้นตอนความพร้อมและอนุมัติในเอกสารนี้ถูกนำออกแล้ว

# ทบทวนงานพัสดุและการปรับระบบ

ทบทวนวันที่ 7 ตุลาคม 2569 ใช้กรอบกลางตามที่ผู้ใช้เลือก ยังไม่กำหนดสังกัดกระทรวงสาธารณสุขหรือ อบจ. ผู้มีอำนาจจึงบันทึกเป็นตำแหน่งและคำสั่งอ้างอิงรายงาน ไม่ตั้งอำนาจอนุมัติจากชื่อ รพ.สต. หรือจากสิทธิ์บัญชีในแอป

## ผลที่นำมาปรับใช้

| งาน | ช่องว่างเดิม | สิ่งที่ปรับแล้ว |
|---|---|---|
| แผน / รายงานขอซื้อหรือจ้าง | มีชื่อรายการ จำนวนเงิน และวิธีเป็นหลัก | เพิ่มสาระรายงาน แหล่งราคา งบประมาณ กำหนดใช้ หลักเกณฑ์ เหตุผลวิธี และตำแหน่ง/คำสั่งผู้มีอำนาจ |
| ผลพิจารณา / สัญญา | อ้างอิงเอกสารเป็นข้อความที่ไม่ตรวจสอบ | เลือกเลขจากทะเบียน เปิดต้นทางได้ และตรวจว่าคำขอ/สัญญาต้นทางผ่านอนุมัติก่อนเสนอเอกสารปลายทาง |
| ตรวจรับ | ไม่มีคำสั่งและหลักฐานผลรับมอบ | เพิ่มคำสั่ง ผู้ตรวจรับ ผลตรวจ จำนวน และหลักฐานรับมอบ พร้อมตรวจข้อมูลก่อนปิดงาน |
| บัญชีวัสดุ / ใบเบิก | มีการตัดยอดแต่ไม่มีหน้าบัญชีรับจ่าย | แสดงรับ จ่าย ยอดหลังรายการ และหลักฐาน เพิ่มผู้เบิก ผู้สั่งจ่าย และผู้รับในใบเบิก |
| ยืม / ซ่อม | ข้อมูลทั้งหมดล็อกหลังอนุมัติ | แก้เฉพาะผลคืน/สภาพรับคืนได้ แสดงงานยืมเกินกำหนดและวันบำรุงรักษา |
| ตรวจสอบประจำปี / จำหน่าย | ไม่มีวันรายงาน คำสั่ง หรือวันลงจ่ายออก | เพิ่มหลักฐานและกำหนดติดตาม แยกวันจำหน่าย วันลงจ่าย และวันแจ้ง สตง. |
| เอกสาร / สิทธิ์ | พิมพ์ได้เฉพาะตาราง และใช้ปุ่มเป็นทางเข้า | พิมพ์แบบร่างรายรายการ ตรวจความพร้อมและล็อกส่วนอนุมัติใน SQL พร้อมทดสอบ RLS |

การออกแบบรายงานและทะเบียนอ้างอิง [ระเบียบกระทรวงการคลัง พ.ศ. 2560](https://sakarat.go.th/doc/law2564/รบ.กระทรวงการคลังว่าด้วยการจัดซื้อจัดจ้า.pdf) ข้อ 21–22 และ 203–219 และให้ตรวจ [กฎหมายพัสดุ/ฉบับแก้ไขของกรมบัญชีกลาง](https://www.cgd.go.th/cs/nbr/nbr/กฎหมาย_พัสดุ.html) ประกอบคำสั่งของหน่วยงาน

## ขั้นตอนที่ใช้ในแอป

1. เจ้าหน้าที่บันทึกร่างและรายละเอียดพร้อมเลขเอกสารอ้างอิง
2. ตรวจรายการความพร้อมในฟอร์ม บันทึกก่อนเปลี่ยนสถานะ
3. เสนออนุมัติ ผู้ใช้ที่มีสิทธิ์บันทึกอนุมัติหรือยกเลิกตามหลักฐานจริง
4. เริ่มดำเนินการ บันทึกผลในช่องที่อนุญาต เช่น ผลตรวจรับหรือคืนพัสดุ
5. ปิดงานหลังหลักฐานผลดำเนินการครบ ดูประวัติก่อน/หลังย้อนหลังได้

สถานะทั้งหกเป็นสถานะติดตามภายใน การกดอนุมัติไม่ได้สร้างลายมือชื่ออิเล็กทรอนิกส์หรือพิสูจน์อำนาจผู้ลงนาม การครบช่องข้อมูลหมายถึงผ่านการตรวจข้อมูลของแอป ไม่ใช่การรับรองความถูกต้องทางกฎหมาย

## กรณีเฉพาะที่แยกไว้

- [ว 804 ลงวันที่ 12 พฤศจิกายน 2568](https://www.moc.go.th/th/file/get/file/2025111345adc18eb5c1fbc972d389b3a989552c140910.pdf) เป็นแนวทางเฉพาะการจัดซื้อครั้งหนึ่งไม่เกิน 50,000 บาท ระบบแสดงแหล่งอ้างอิงเมื่อเป็นงานซื้อในช่วงวงเงินนี้ แต่ยังใช้ฟอร์มแบบเต็ม ไม่เลือกข้อยกเว้นหรือเปลี่ยนวิธีให้อัตโนมัติ งานจ้างไม่ถูกจัดเข้าแนวทางนี้จากวงเงินเพียงอย่างเดียว
- วันครบรายงานตรวจสอบประจำปีให้เจ้าหน้าที่ตรวจวันทำการและวันหยุดจริงก่อนบันทึก ระบบไม่เดาวันหยุดของหน่วยงาน
- งานตรวจรับและใบเบิกยังไม่ทำรายการคลังอัตโนมัติ ผู้ควบคุมทำรายการคลังแยกพร้อมเลขหลักฐาน จึงต้องตรวจไม่ให้รับ/จ่ายซ้ำ
- การจำหน่ายบันทึกกระบวนการและวันลงจ่าย โดยยังไม่เปลี่ยนสถานะทะเบียนครุภัณฑ์หรือตัดบัญชีอัตโนมัติ

## ฐานข้อมูลและการอัปเกรด

- โครงการ Supabase ใหม่: รัน `supabase/schema.sql` ครั้งเดียว
- โครงการที่เคยใช้ schema เดิมแล้ว: รัน `supabase/migrations/202610070001_procurement_workflow.sql` แล้ว `supabase/migrations/202610070002_stock_card_values.sql` ตามลำดับ ไม่รัน schema สร้างตารางซ้ำ
- Migration เพิ่มตัวตรวจความพร้อม และเปิดเฉพาะช่องผลดำเนินการที่กำหนด ข้อมูลเดิมไม่ถูกเติมคำสั่งหรือหลักฐานสมมติให้
- เอกสารเดิมที่ข้อมูลยังไม่ครบจะถูกปฏิเสธเมื่อเปลี่ยนสถานะ ต้องตรวจและเติมข้อมูลในระยะที่แก้ไขได้ ข้อมูลตัวอย่างเก่าที่ผู้ใช้แก้ไว้ยังคงเดิม

## ผลทดสอบและขอบเขตที่ยังเหลือ

ทดสอบ SQL บน PostgreSQL ผ่าน PGlite ในเครื่อง ใช้ `auth.uid()` จำลองและบัญชีสี่บทบาท ตรวจการสร้าง schema การใช้ migration การเสนอรายงาน การล็อกเนื้อหา การบันทึกผลคืน การป้องกันยอดติดลบ และ RLS ทดสอบเบราว์เซอร์จริงสำหรับฟอร์ม เอกสารพิมพ์ บัญชีวัสดุ และขั้นตอนปิดงาน

ยังไม่ได้เชื่อม Supabase จริงเพื่อทดสอบ Auth/PostgREST การรับจ่ายพร้อมกันหรือ backup ยังไม่มีรายการย่อยต่อเอกสาร ไฟล์แนบจริง การเชื่อม e-GP ระบบเบิกเงิน/ภาษี และลายมือชื่อดิจิทัล เอกสารพิมพ์เป็นแบบร่างภายในสำหรับตรวจทาน ระบบนี้ใช้กับหน่วยงานเดียว
