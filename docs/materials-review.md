# ทบทวนระบบวัสดุ วันที่ 7 ตุลาคม 2569

ขอบเขตปัจจุบันคือคำนวณ จัดเก็บข้อมูล และรายงานวัสดุเท่านั้น ครอบคลุมทะเบียน รับจ่าย Stock Card ตรวจนับ และประวัติการแก้ไข ไม่รวมครุภัณฑ์ ค่าเสื่อม ขั้นตอนจัดซื้อ หรือเสนออนุมัติ

ทบทวนจาก [คู่มือบริหารงานพัสดุ สำนักงานเขตพื้นที่การศึกษาประถมศึกษานครสวรรค์ เขต 2](https://www.nsw2.go.th/wp/wp-content/uploads/2024/06/kes_manual.pdf) โดยนำหลักการควบคุมทะเบียน หลักฐานรับจ่าย และการตรวจนับมาใช้กับฟังก์ชันบันทึกและรายงาน ไม่ได้ใช้แทนระเบียบหรือคำสั่งมอบอำนาจของหน่วยงาน

| เรื่อง | ฟังก์ชันที่เพิ่ม |
| --- | --- |
| จำแนกและค้นหาวัสดุ | หมวดวัสดุ ตัวกรองของหมดและถึงจุดสั่งซื้อ |
| ตรวจสอบหลักฐานรับจ่าย | เลขหลักฐาน ผู้ส่ง/ผู้รับ หน่วยงาน ในรายการและ Stock Card |
| สรุปการเคลื่อนไหว | รายงานตามช่วงวันบันทึก ยกมา รับ จ่าย คงเหลือ มูลค่ารับ/จ่าย |
| เปรียบเทียบยอดตรวจนับ | บันทึกวัน ผู้ตรวจ จำนวนจริง และยอดบัญชี ณ บันทึกผล คำนวณผลต่าง |
| ใช้ข้อมูลต่อ | CSV และพิมพ์/PDF ของรายงาน |

การตรวจนับไม่ปรับยอดคลังอัตโนมัติ ประวัติการแก้ผลตรวจนับอยู่ในประวัติรายการ Stock Card โหลดการเคลื่อนไหวทั้งหมด (Supabase แบ่งอ่านครั้งละ 1,000 รายการ) ส่วนประวัติการแก้ไขแสดง 200 รายการล่าสุด

มูลค่ารับจ่ายใช้จำนวนคูณราคาต่อหน่วยที่เก็บในรายการนั้น ไม่ใช่วิธี FIFO หรือราคาถัวเฉลี่ย รายการเดิมที่ไม่มีราคาจะแสดงเป็นรายการไม่ทราบราคาในรายงาน ผลรวมมูลค่าจึงครอบคลุมเฉพาะรายการที่มีราคา มูลค่าคงเหลือในทะเบียนใช้ราคาปัจจุบัน

ยอดยกมาอาศัยยอดคงเหลือที่เก็บในประวัติรับจ่าย หากไม่มีประวัติเลยใช้ยอดปัจจุบัน ข้อมูลที่เริ่มบันทึกกลางปีหรือประวัติไม่ครบควรตรวจเทียบหลักฐานก่อนใช้รายงานย้อนหลัง

ตัวอย่างวัสดุ 3 รายการมีกรณีคงเหลือปกติ ต่ำกว่าจุดสั่งซื้อ และหมดคลัง ระบบไม่ทับข้อมูลตัวอย่างที่ผู้ใช้แก้ไว้

ฐานข้อมูลใหม่ใช้ `supabase/schema.sql` โครงการเดิมอัปเกรด migration ตามลำดับถึง `202610070005_materials_reports.sql` ข้อมูลครุภัณฑ์และโมดูลเดิมยังเก็บอยู่ แต่ไม่แสดงและไม่ให้แก้ผ่านสิทธิ์แอปปัจจุบัน ยังไม่ได้นำขึ้น Supabase จริง

ตรวจสอบผ่าน Node/PostgreSQL จำลอง 19 กรณี และ Chrome 17 จุด รวมหลักฐานรับจ่าย การห้ามจ่ายเกินยอด รายงานช่วงวัน และผลต่างตรวจนับ
